# 取词管线「仿原生」架构说明(v0.5.0 · 推倒重来版)

本项目(App 名「跃文」)的 iPad 取词交互原则:
**在不可用 PDFKit 内置选择的前提下,尽量用系统公开组件 + 逐条对标原生行为。**
本文档 = 研究结论 + 原生对照表 + 取舍记录。

## 0. v0.5.0 变更摘要(推倒重来)

删除旧协调器的全部补丁层,重写为:

- `Sources/Reader/Selection/ReaderCoordinator.swift` —— 单一交互状态机(重写);
- `Sources/Reader/Selection/SelectionKit.swift` —— 拖柄 / 系统放大镜封装 / Pencil 感知手势 / 几何校验;
- `Sources/Reader/Selection/SelectionMenu.swift` —— 系统编辑菜单封装(UIEditMenuInteraction)。

修复上一版与原生体验的已知差距:

1. **拖动过程中拖柄实时显示**(旧版拖动时拖柄消失,松手才出现);
2. **放大镜只对指尖显示**(Pencil 操作不显示放大镜——原生如此;长按识别器与 Pencil 感知 pan 区分);
3. **菜单弹出/收起时机**对齐原生:按住 ~0.35s 菜单先弹出;一旦开始拖动立即收起;松手重新弹出;拖柄调整结束也重新弹出;
4. 新增**贴边自动滚动**:拖动到屏幕上下边缘时内容自动滚动、选区跟随(在"冻结滚动"之上由自研逻辑实现,只写 contentOffset,不触发任何 PDFKit 自动行为);
5. 旋转/缩放/连续滚动下的坐标全部实时换算(新增 `pdfView.bounds` 观察,旋转后拖柄立即归位)。

- **竖线 = 首/末行选区高**(随页面缩放自适应;多行选区各取首行/末行的高度)——v0.8.0 的"固定 32pt 线长"作废(以最新要求为准);**圆点保持定尺寸**(14pt)紧贴竖线外端、位于选区外(起点在上端、终点在下端),与线交叠 2pt 消缝;
- 两端**共用同一几何函数**(`SelectionHandleView` 内 `lineFrame`/`dotFrame` 按 `isStart` 镜像),线宽/圆点/交叠/热区全部集中在 `HandleMetrics`,方便调参;`refreshHandles` 摆放公式:起点框顶 = 首行.minY − dotProtrusion、终点框底 = 末行.maxY + dotProtrusion;
- **拖动热区 ≥44×44pt**(`point(inside:)` 扩边,以"圆点+竖线"整体为中心);**与"按住选区本体拖动"互不冲突**——长按落点先过 `handleHitTest`(命中拖柄热区即让位给拖柄 pan,不再启动本体拖动/新选词);
- 浅色/深色页面上均清晰可见(实心 systemBlue 圆点 + 竖线,圆点带细阴影;沿用 v0.6.8 要求,不加白描边)。

## 1. 为什么不用 PDFKit 内置选择机制

- iOS 18 起 PDFKit 已知回归:
  - `PDFPage.characterBounds(at:)` 返回错误坐标(开发者反馈 FB14843671,至 18.4 未修复);
  - `page.string` / `attributedString` 文本顺序错乱,部分文本跑到页面末尾附近(FB16264926)。
- 真机实证(两个非线性化样本 PDF:FreePic2Pdf 扫描书 / iText+InDesign 教材):
  触发内置选择后 **52ms 内跳到文档最后一页**,并伴随 **6 秒级卡死**;改用"规范化读取副本"后仍会复现。
- 结论:内置选择机制在异常文档上不可用。本管线:
  - **停用**内置长按/双击选择手势(保留滚动、缩放、链接单击);
  - **全程不设置** `PDFView.currentSelection`(唯一例外:用户"取消选中"时调用 clear,历史日志证明安全);取词只用点坐标 API:`selectionForWord(at:)` / `selectionForLine(at:)` / `selection(from:to:)`。

## 2. 候选方案调研(2026-10)

| 候选 | 结论 |
|---|---|
| `UITextInteraction` + `UITextSelectionDisplayInteraction`(真·原生选择组件链) | 需要完整的 `UITextInput` 一致性实现;其位置/几何依赖索引级文本,而索引级文本在问题文档上不可靠 → 需先引入 PDFium 级文本引擎(大工程),**暂不采用,列为后续可选升级** |
| VisionKit Live Text(`ImageAnalysisInteraction`) | 系统级取词(真·原生件),但要求把页面渲染为位图 + 逐页 Vision 分析,缩放清晰度/性能/铅笔支持均有代价 → 不采用 |
| PDFium(Chrome 的 PDF 引擎,BSD-3) | 只是文本/渲染引擎,不带交互 UI;可作未来"索引级文本"升级件 |
| MuPDF | AGPL,许可不合要求 |
| pdf.js | Web 栈,需把阅读器整体搬进 WKWebView,Pencil 与原生体验难保证 |
| PDFEditorSDK(MIT,小项目) | 只有批注画笔,无文本选择;可作 M4 铅笔标注参考 |
| **总结** | **无现成可用件** → 自研管线 + 系统组件(放大镜/菜单)+ 逐条对标原生 |

## 4. 有意保留的差异与理由

1. **~~词粒度吸附~~ → 字符粒度(v0.6.5 用户要求)**:拖选改为一个字母一个字母地延伸——用 `selection(from:to:)`(原始触点,字符边界收口),不依赖已损坏的字符索引 API;长按初始仍整词选中。
2. **拖动期冻结滚动**:历史修复(拖动被滚动抢走→跳页)的稳定器;贴边自动滚动由自研逻辑接管。
3. **点选区内 = 只切换编辑栏、永不关闭选区**(用户明确要求"编辑栏关闭 ≠ 选区关闭");点空白则与原生一致——选区与编辑栏**一起消失**。
4. **三击取整行**:PDF 无可靠段落结构;行是安全近似(后续可由 M2 整句卡升级为整句)。
5. **跨页选择暂不支持**:与取词/词卡产品语义一致。

## 5. 稳定性设计(为什么不会再跳页/卡死)

1. 不设置 `PDFView.currentSelection`(绕过 PDFKit 内部选区解析路径);
2. 选区全部由 `selectionForWord/Line/from:to:` 点坐标 API 构造,绕过 iOS 18 索引回归;
3. `isSane` 校验(单页、≤6000 字符、≤150 行)+ 矩形有效性/页面边界拒绝;
4. 跳页护栏(选区变化后 0.8s 窗口内的跨页前跳自动拉回);
5. 拖动期冻结滚动由自身控制;贴边滚动直接写 `contentOffset`,速度封顶、越界钳制;
6. 全量诊断日志(`DiagLog`),内置诊断页可随时查看。
